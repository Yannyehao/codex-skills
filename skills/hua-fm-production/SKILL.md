# 华罗庚 FM 制作

目标是把独立生成的短镜头接成一期连续的数学播客。人物始终像在面对观众，机位和身份稳定，表演有自然节奏。按用户当前要验证的结果决定交付长度。

## 开工前

1. 从当前工作区定位项目 Git 根。若当前工作区没有该项目，读本 Skill 目录中的 `config.local.json` 的 `project_root`。项目识别以 `docs/GROK_PROMPT_LIBRARY.md` 和 `config/ep01_production_state.json` 为准。
2. 读项目 `AGENTS.md`、`PLAN.md` 的当前状态、`DEVLOG.md` 顶部和提示词库相关章节。按当前任务查最近裁决、原词、参考片、锚帧和已确认过的 Grok 入口。用户说某段好，只沿用认可的范围。
3. 标明本轮是同图首尾的独立生成、原视频 Extend，还是正式成片推进。有不同输入的历史实验保留为对照。用户要验两段接缝时，从两段做起，交接在一条短视频里。

## 提示词与生成

- 同图首尾时，在 Grok 的首帧和末帧槽分别指定同一张图。继承当前已确认的参考图、画幅、时长和静音设置。提交前核对两个槽，提交后各自记录会话、帖子、实际原词与原片。
- 先比较同输入方式下已获认可的**整份原词**。项目提示词库的 E013-O 固定段和 B、G 是目前同图首尾的可复用参照。B 对应轻强调，G 对应正文常态。两条在旧锚图上获局部认可，迁移效果按新片判断。v4 是原有运动上下文里的整体表演参照。
- 保留节目正在进行、人物面对观众、动作小而有起落的意图。口型留给正式旁白，底片只限制嘴部。避免把整段写成无所事事地静坐，也避免让底片表演一整句的起落。按剧情需要选动作，手势可有可无。优先复用已获认可的原词，必要的改动写进本轮记录。
- 不因一个失败样本就断定某个词的作用。记录当时的模式、输入、提示词与房间、脸、眼神、身体、手纸的实际变化。

## 验收与交付

1. 保留原片，核对实际帧率、帧数和音轨。优先输出直拼基线，检查接点前后的亮度、脸、手、纸和运动方向。需要时复用已有局部首尾校正，共用帧保留一次，明确修了哪几帧。
2. **接缝与段内表演都要过。** 原速从头看完，人物要清醒自然、有交流感。复查脸与身体比例、眼睛闪动、明显张嘴、手纸异常及回位跳变。逐帧数据只能解释画面问题。若只能抽帧，明确标注原速观感仍待核验。
3. 交可播放的实际样片、接点时间码和未过项。用户要求无声接点实验时交该实验。正式成片在无声底片通过之后按项目流程配旁白与口型，按用户要求交从 00:00 开始的累计版。
4. 将原词、输入、设置、结果帖、时间码、用户裁决和可复用范围写回项目提示词库、DEVLOG 与既有 Notion 迭代记录。接点可用而表演退回时，保留两项实际裁决。

## 维护

项目提示词、样片和裁决留在项目里。用户改了长期工作方法，或有实片证据表明本流程漏检，才更新 Skill。源文件在个人 `codex-skills` 仓库中。按仓库要求校验、安装、核对安装副本、提交和推送。机器路径、项目私有链接、素材及会话证据只留本机配置或项目记录。
